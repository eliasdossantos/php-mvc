CLI e geradores

Lista verificada de comandos PHP MVC e opções reconhecidas.

Ajuda

php mvc help
php mvc list

O parser aceita argumentos posicionais, flags --flag e pares --chave=valor.

Geradores

ComandoArtefato
make:controller NomeController Web
make:api-controller NomeController API em Api/
make:model NomeModel
make:request Nome / make:api-request NomeFormRequest
make:api-resource NomeTransformação explícita JSON
make:service Nome, make:repository NomeCamadas de aplicação
make:migration Nome, make:seed NomeBanco
make:view nome, make:layout nomeTemplates

O gerador não sobrescreve arquivos existentes sem autorização explícita. Confira e complete o stub antes de usar em produção.

Banco e utilitários

php mvc migrate
php mvc migrate --fresh
php mvc migrate:rollback --step=2
php mvc seed
php mvc seed:run UserSeeder
php mvc key:generate
php mvc serve --port=8080

migrate --fresh recria o banco inteiro e pede confirmação; operação destrutiva. serve inicia servidor local, por padrão porta 8000. A lista oficial em execução é php mvc list.

Nomes

Geradores aceitam separadores de subpasta normalizados; nomes de classe são convertidos a PascalCase. Consulte código gerado: pluralização para nomes de tabela é simples e pode exigir ajuste manual.

Ciclo seguro de geração e migração

Comece com `help`/`list`; gere um stub e leia-o antes de executar. Geradores de Controller, Model, Request, Service, Repository, View/Layout e API escrevem sob app/, resources/views/ ou database/. O CLI não substitui o registro manual da rota nem a revisão de autorização.

php mvc list
php mvc make:controller Admin/ReportController
php mvc make:request Admin/FilterReportRequest
php mvc make:repository Admin/ReportRepository
php mvc make:migration create_reports_table
php mvc migrate

Arguments posicionais seguem o nome do comando; opções aceitam `--flag` ou `--key=valor`. O gerador pula arquivo existente em vez de sobrescrevê-lo automaticamente. Confira namespaces, tabela e fillable gerados antes de usar.

Quando usar e o que não delegar ao CLI

Use o CLI para rotinas locais previsíveis: migrations pendentes, rollback conscientemente revisado, seed de desenvolvimento e stubs. Para produção, deployment/migração deve seguir backup e janela operacional da aplicação; confirmação interativa de `--fresh` não é proteção contra escolher o database errado.

UserSeeder contém contas/senhas de demonstração. Inspecione a pasta database/seeds antes de `seed:run` sem argumento, porque o comando inclui todos os arquivos *Seeder.php. Consulte Migrations e Seeders.

Flags destrutivas e servidor local

migrate --fresh aceita --force e --yes; force libera execução em produção e yes pula a confirmação do nome do banco. São opções destrutivas: não as use sem revisar ambiente/alvo e backup.

# Exemplo de desenvolvimento; apaga e recria o banco configurado.
php mvc migrate --fresh --force --yes

# Servidor PHP de desenvolvimento, com host e porta explícitos.
php mvc serve --host=127.0.0.1 --port=8080

php mvc seed executa a lista ordenada de database/seeds/DatabaseSeeder.php. seed:run sem nome percorre os arquivos *Seeder.php em ordem natural, ignorando o arquivo principal; com nome, executa somente o Seeder indicado. O UserSeeder fornecido é uma classe que usa o Model User e a função nativa PHP password_hash(); o runner envolve cada classe em uma transação. O tratamento de arrays/arquivos procedurais e de duplicatas MySQL 1062 existe apenas para compatibilidade com Seeders legados.

make:model e make:migration são geradores distintos. O primeiro imprime uma sugestão de migration SQL, mas o Migrator carrega arquivos PHP que retornam Migration; use make:migration para criar o arquivo executável. Para make:view admin/product, o caminho gerado fica sob resources/views/admin/product e a notação para a subview inclui esse segmento (admin.product.index).

O gerador pode retornar sucesso mesmo quando um arquivo existente foi ignorado; confira o caminho/saída após execução. serve --host=0.0.0.0 expõe o servidor de desenvolvimento na interface de rede — prefira loopback salvo necessidade concreta.

Subpastas: suporte varia por gerador

Não aplique a regra de subpastas a todos os comandos. make:controller, make:request, make:view e make:layout preservam subpastas/namespaces nos respectivos destinos. Em contraste, make:model, make:service, make:repository, make:seed e os geradores make:api-* normalizam o nome e escrevem na raiz do diretório do recurso. Confirme a mensagem e o caminho gerado antes de ajustar imports; por exemplo, não espere que make:repository Admin/ReportRepository gere automaticamente app/Repositories/Admin/.

make:model não gera migration

O comando cria o Model e imprime uma dica textual de nome terminada em .sql; não cria arquivo SQL nem migration executável. O Migrator carrega arquivos PHP de database/migrations/*.php que retornam Framework\Database\Migration. Para criar uma migration executável, use php mvc make:migration create_nome_table, edite o PHP gerado e só então execute php mvc migrate. Não crie o arquivo .sql sugerido esperando que o Migrator o execute.

Seeders: plano principal versus execução por diretório

Há dois comandos com seleção intencionalmente distinta. php mvc seed usa a ordem explícita do arquivo principal; php mvc seed:run sem nome roda os arquivos de dados *Seeder.php em ordem natural e exclui DatabaseSeeder.php. php mvc seed:run UserSeeder roda somente aquele arquivo; php mvc seed:run DatabaseSeeder delega ao plano principal.

Um plano principal vazio é válido e termina com zero Seeders executados. Se seed:run não encontrar classes/arquivos, o comando exibe um aviso de ausência, sem mensagem de sucesso.

php mvc migrate
php mvc seed
php mvc seed:run UserSeeder
php mvc seed:run

Os Seeders novos são classes em Database\Seeders que estendem Framework\Database\Seeder e implementam run(): void. O runner inicializa o ambiente, usa a conexão singleton e envolve cada classe em uma transação. Ele não injeta helper de senha: use password_hash($senha, PASSWORD_DEFAULT) ou um método de Model existente, como User::createWithHash(). Use Models dentro de run(); as antigas formas array/procedural continuam somente por compatibilidade. O resumo conta Seeders executados, não linhas inseridas. Em classes, erros propagam e revertem o Seeder atual; a regra de ignorar MySQL 1062 existe apenas no caminho legado de arrays.

O comando executa arquivos PHP confiáveis de database/seeds/. Não rode um repositório ou seeder desconhecido contra um banco importante; use uma base local, revise as linhas e confirme a configuração do ambiente.
