Seeders

Inicialize dados por classes Seeder, usando os Models e a conexão do framework sem SQL manual.

Um Seeder é uma classe que inicializa dados previsíveis para desenvolvimento, testes ou configuração inicial. No PHP MVC, o Seeder novo estende Framework\Database\Seeder e implementa run(): void. O runner central carrega o ambiente, usa a conexão singleton de Database e envolve cada execução em uma transação; dentro de run(), você trabalha com Models.

Arquivos e responsabilidades

  • database/seeds/DatabaseSeeder.php: retorna a lista ordenada de classes de Seeder para o comando principal.
  • database/seeds/*Seeder.php: arquivo PHP de cada Seeder; a forma recomendada declara uma classe no namespace Database\Seeders.
  • framework/Database/Seeder.php: classe abstrata base com o contrato run(): void.
  • cli/SeedRunner.php: resolve os arquivos, executa run(), inicializa o bootstrap e controla a transação por Seeder.
  • cli/Commands/SeedCommand.php e SeedRunCommand.php: conectam o runner aos comandos seed e seed:run.

O runner inclui os arquivos de database/seeds/ diretamente; não foi necessário acrescentar um novo mapeamento PSR-4 ao Composer. Os Models da aplicação continuam sendo carregados pelo autoload já existente. Por isso, o Seeder não precisa conter require, construir PDO, carregar .env ou escrever SQL.

Comandos disponíveis

ComandoO que executaQuando usar
php mvc make:seed ProductSeederGera database/seeds/ProductSeeder.php como classe em Database\Seeders, estendendo a classe base.Iniciar um Seeder novo. Confirme antes que o Model e sua tabela existem.
php mvc seedExecuta as classes listadas em DatabaseSeeder.php, na ordem escrita.Inicialização principal, previsível e recomendada.
php mvc seed:runExecuta arquivos *Seeder.php em ordem natural pelo nome; ignora DatabaseSeeder.php.Executar o conjunto encontrado no diretório.
php mvc seed:run UserSeederExecuta apenas UserSeeder.php; aceita também o sufixo .php.Testar um Seeder isoladamente.
php mvc seed:run DatabaseSeederAlias de execução do plano principal.Compatibilidade com a forma nomeada do comando.

O resumo dos comandos class-based informa quantos Seeders terminaram; ele não estima quantidade de linhas, pois run(): void não retorna contadores. As mensagens de progresso indicam o início e o sucesso de cada run(). Um plano principal vazio é válido e resulta em zero Seeders executados; se seed:run não encontrar arquivos, o CLI mostra aviso de ausência.

Execute as migrations antes de semear: php mvc migrate. A conexão vem da configuração existente em config/database.php e do .env carregado pelo bootstrap do framework. O wrapper de banco atual usa PDO/MySQL; não há suporte a SQLite nele.

O Seeder principal e a ordem explícita

Cenário e objetivo. Alguns dados dependem de outros. O plano principal estabelece a ordem sem depender da ordenação incidental dos arquivos.

<?php

namespace Database\Seeders;

return [
    RoleSeeder::class,
    UserSeeder::class,
    ProductSeeder::class,
];

::class produz uma string com o nome da classe; não cria uma instância. O runner valida todos os arquivos antes de iniciar o plano, depois executa cada run() na ordem do array. O arquivo fornecido pelo projeto retorna [UserSeeder::class]. Não inclua DatabaseSeeder::class na própria lista. Use o namespace convencional Database\Seeders para que a execução por diretório possa resolver os arquivos automaticamente; quando necessário, runMain() e runOne() também aceitam a classe-string totalmente qualificada de uma classe cujo arquivo esteja em database/seeds/.

Resultado esperado: o CLI mostra [SEED] NomeSeeder na ordem configurada e só avança depois de a transação daquele Seeder ser confirmada. Se um nome não resolver para arquivo ou uma execução lançar exceção, o comando para; os Seeders anteriores do plano, já confirmados, não são revertidos.

Estrutura de uma classe Seeder

Cenário e objetivo. Criar ou localizar dados iniciais de usuários usando o Model existente, sem tratar de conexão ou INSERT no arquivo do Seeder.

<?php

namespace Database\Seeders;

use App\Models\User;
use Framework\Database\Seeder;

class UserSeeder extends Seeder
{
    public function run(): void
    {
        $users = new User();

        $users->firstOrCreate(
            ['email' => 'admin@example.com'],
            [
                'name'     => 'Administrador',
                'password' => password_hash('admin123', PASSWORD_DEFAULT),
                'role'     => 'admin',
                'active'   => 1,
            ]
        );
    }
}

O que acontece: o runner instancia UserSeeder sem argumentos e chama run(). A classe usa o Model User e seu firstOrCreate() para procurar pelo e-mail; se não houver linha visível, cria uma usando os atributos fornecidos. O Model filtra os campos por $fillable e aplica os timestamps configurados nele. A classe fornecida pelo projeto segue esse padrão para duas contas de demonstração.

Retorno e falhas: run() retorna void. Não retorne um array de registros em um Seeder class-based. Exceções do Model ou do banco propagam para o runner e revertem a transação desse arquivo.

Usar Models dentro do Seeder

Os Models deste framework são baseados em instâncias, não em chamadas estáticas. Use (new User())->where(...) ou crie uma variável; chamadas como User::where(...) e User::create(...) não correspondem à API real. O Seeder não cria uma camada ORM adicional: ele reaproveita os métodos existentes em Framework\Database\Model.

$users = new User();
$existing = $users->where('email', 'admin@example.com')->first();

if ($existing === false) {
    $users->create([
        'name'     => 'Administrador',
        'email'    => 'admin@example.com',
        'password' => password_hash('admin123', PASSWORD_DEFAULT),
        'role'     => 'admin',
        'active'   => 1,
    ]);
}

first() retorna um objeto ou false; firstOrFail() retorna um objeto ou lança RuntimeException; create() retorna o ID inserido como string ou false. Prefira firstOrCreate() quando as colunas de busca e os valores de criação se encaixarem no seu caso. Nenhum desses métodos faz hash de senha automaticamente. Você pode gerar o hash com password_hash($password, PASSWORD_DEFAULT) antes de create()/firstOrCreate(), ou usar o método específico $users->createWithHash(array $data): string|false, que aplica bcrypt e define role=member/active=1 quando omitidos. Use somente uma estratégia; passar um valor já hashado a createWithHash() faria hash duplo.

Buscar registros relacionados

Há uma relação de chave estrangeira real entre api_tokens.user_id e users.id. O framework não oferece neste momento propriedades de relação como $user->tokens nem um método estático de relacionamento; consulte explicitamente o Model relacionado pela chave estrangeira. Isso continua sendo uma consulta por Model, não SQL manual:

<?php

namespace Database\Seeders;

use App\Models\ApiToken;
use App\Models\User;
use Framework\Database\Seeder;

class AuditExistingTokensSeeder extends Seeder
{
    public function run(): void
    {
        $user = (new User())
            ->where('email', 'admin@example.com')
            ->firstOrFail();

        $tokens = (new ApiToken())
            ->where('user_id', (int) $user->id)
            ->get();
    }
}

$tokens será uma lista de objetos e pode estar vazia. Quando a dependência é obrigatória, firstOrFail() deixa claro o problema: se o registro relacionado não existir, lança uma exceção e o Seeder atual é revertido. Coloque o Seeder que cria o registro antes do dependente no plano principal.

Limite importante do exemplo pedido: o projeto fornecido não contém App\Models\Status, tabela statuses ou coluna users.status_id; além disso, status_id não está no $fillable de User. Portanto, o exemplo Status::where(...) / User::create(...'status_id'...) não é executável neste framework como está. Se um aplicativo adicionar sua própria migration, Model e campo permitido, a chave estrangeira poderá ser buscada e atribuída explicitamente com instâncias de Model; isso não cria automaticamente uma API de relacionamentos que hoje não existe.

Hash de senha com PHP nativo

Função: password_hash(string $password, string|int|null $algo, array $options = []): string é uma função interna do PHP, não uma API do MVC. Em arquivos namespaced, como os Seeders em Database\Seeders, a chamada não precisa de import: PHP resolve a função interna quando não existe uma função homônima nesse namespace. Use PASSWORD_DEFAULT para adotar o algoritmo recomendado pelo PHP e permitir sua evolução.

$hash = password_hash('password', PASSWORD_DEFAULT);
$isValid = password_verify('password', $hash);

Parâmetros: $password é a senha original; $algo define o algoritmo (use PASSWORD_DEFAULT); $options é opcional e só deve ser informado se houver uma necessidade técnica concreta. Retorno: uma string de hash que inclui os dados necessários para verificação. O salt é gerado pela função; não crie nem reutilize um salt manualmente. password_verify() devolve booleano e é a forma correta de comparar uma senha com o hash.

Em um Seeder que usa firstOrCreate() ou create(), gere o hash no campo persistido, como nos exemplos acima. O Model não transforma automaticamente uma senha passada a esses métodos. O Model User também oferece createWithHash(), que recebe a senha em texto puro e gera o hash internamente; escolha um caminho ou o outro, nunca os combine, para evitar hash duplo.

Exemplo: criar um Seeder de produtos

Cenário e objetivo. Popular uma tabela products já existente para validar um catálogo local. Este exemplo pressupõe que App\Models\Product, a migration/tabela e os campos permitidos em $fillable já foram criados pelo aplicativo; não são recursos incluídos no projeto base.

  1. Gere a estrutura com php mvc make:seed ProductSeeder; o comando cria um arquivo de classe e não sobrescreve um arquivo existente.
  2. Confirme o nome da tabela, as colunas e o $fillable do Model. Rode php mvc migrate antes de inserir dados.
  3. Implemente run() com o Model, depois teste somente esse arquivo.
  4. Quando fizer parte do fluxo normal do projeto, acrescente ProductSeeder::class ao plano principal.
<?php

namespace Database\Seeders;

use App\Models\Product;
use Framework\Database\Seeder;

class ProductSeeder extends Seeder
{
    public function run(): void
    {
        $products = new Product();
        $products->firstOrCreate(
            ['name' => 'Product Example'],
            ['price' => 100.00]
        );
    }
}
php mvc make:seed ProductSeeder
php mvc seed:run ProductSeeder
# Depois de incluir ProductSeeder::class no DatabaseSeeder.php:
php mvc seed

Resultado esperado: o Model consulta por name e cria a linha somente quando não encontra uma correspondência visível. Se a tabela ou coluna não existir, o banco lança erro e a transação desse Seeder é revertida. Ajuste os atributos a um índice único apropriado se precisa de repetibilidade confiável.

Repetição, duplicatas e transações

A transação do runner cobre todo o run() de cada classe. Se uma operação falhar, apenas a transação daquele arquivo é revertida. No plano principal, Seeders anteriores já confirmados permanecem. Uma classe não recebe um tratamento especial de erro 1062: use firstOrCreate() ou outra regra explícita de idempotência e mantenha constraints no banco. Se um registro está soft-deletado mas ainda viola uma chave UNIQUE, a busca do Model pode não vê-lo e a tentativa de inserção pode falhar; trate esse caso deliberadamente.

Os arquivos legados que retornam arrays continuam aceitos por compatibilidade, mas não usam Models: o runner monta INSERT preparado, processa o campo password em texto e ignora somente erro MySQL 1062. Essa regra pertence ao caminho legado; não conte com ela para esconder erros em Seeders class-based.

Compatibilidade com Seeders antigos

Arquivos antigos que retornam uma lista de linhas ou o descriptor ['table' => ..., 'records' => ...] continuam sendo executados. Arquivos procedurais sem retorno explícito também continuam incluídos, mas o runner não consegue envolver suas próprias operações em uma transação nem centralizar acesso ao Model. Em PHP, require devolve 1 quando não existe return; um return null explícito segue igualmente o caminho legado. Como não é possível distinguir esse sentinel de um return 1, não use inteiros como resultado. Migre gradualmente para classes que estendem Seeder; não misture um return array de dados com a expectativa de que run() também seja chamado.

Erros comuns e como corrigir

  • Classe/arquivo não encontrado: mantenha o arquivo em database/seeds/, use o nome-base com sufixo Seeder e confirme que o item de DatabaseSeeder.php resolve para esse arquivo.
  • Classe não estende Seeder: importe Framework\Database\Seeder, estenda-o e implemente public function run(): void.
  • Construtor exige parâmetros: o runner instancia a classe sem argumentos; deixe a conexão e dependências do framework no bootstrap/Model.
  • Model não encontrado ou coluna não permitida: verifique a classe, migration, nome da tabela e $fillable. create() retorna false se nenhum campo sobreviver ao filtro.
  • Registro relacionado não encontrado: execute primeiro o Seeder pai e use firstOrFail() apenas para dependências obrigatórias; caso seja opcional, trate o retorno de first() igual a false.
  • Senha não autentica: use password_hash($senha, PASSWORD_DEFAULT) antes de create()/firstOrCreate(), ou passe o texto puro a createWithHash(); nunca grave texto puro nem gere hash duplo.
  • Erro de conexão: rode as migrations e revise .env e config/database.php; não replique esse bootstrap dentro do Seeder.

O que evitar e limites reais

  • Não use PDO, prepare(), execute(), SQL manual, require ou carregamento de .env em Seeder novo; use Models e deixe o runner gerenciar o ambiente.
  • Não use sintaxe estática User::where()/User::create(): os métodos de Model são de instância.
  • Não presuma relação automática, accessor de foreign key, modelo Status, coluna status_id, observer ou cast: verifique recursos presentes no projeto.
  • Não espere um helper Hash() do framework: Seeders novos usam password_hash() do PHP ou um método de Model já existente, como User::createWithHash().
  • Não grave tokens/credenciais reais em fixtures versionadas. A conta Admin deste projeto é de demonstração e usa credenciais previsíveis; altere/remova antes de qualquer ambiente exposto.
