Início

Visão Geral

Boilerplate PHP puro (sem dependência de frameworks de terceiros) com arquitetura MVC em camadas. Router desacoplado, ORM mínimo estilo Active Record, autenticação completa, CLI próprio para scaffolding e um conjunto de classes Core\* genéricas e reutilizáveis em qualquer projeto.

De composer create-project ao servidor local com autenticação completa funcionando em minutos.

Instalação

Requer PHP 8.1+, Composer e um banco de dados MySQL/MariaDB (driver configurado em config/database.php).

terminal
# 1. Clonar o repositório
git clone https://github.com/eliasdossantos/php-mvc.git meu-projeto
cd meu-projeto

# 2. Instalar dependências (gera vendor/ e copia .env.example → .env automaticamente
#    via o script post-create-project-cmd do composer.json)
composer install

# 3. Gerar a APP_KEY da aplicação
php mvc key:generate

# 4. Configurar o .env (nome do app, banco de dados, e-mail — ver seção Configuração)
nano .env

# 5. Criar o banco de dados vazio (o nome deve bater com DB_DATABASE do .env)
mysql -u root -e "CREATE DATABASE app_db CHARACTER SET utf8mb4"

# 6. Rodar as migrations (cria as tabelas users, password_resets, rate_limits...)
php mvc migrate

# 7. Subir o servidor de desenvolvimento embutido do PHP
php mvc serve
# 🚀  PHP MVC App rodando em: http://localhost:8000
💡
Alternativa via composer scripts

composer run serve também sobe o servidor (equivalente a php -S localhost:8000 -t public), e composer run test executa a suíte PHPUnit (tests/Unit e tests/Feature).

Servidor de produção (Apache)

O public/ deve ser o document root do virtual host. O arquivo public/.htaccess já reescreve todas as requisições para public/index.php via mod_rewrite. Para Nginx, use um try_files $uri $uri/ /index.php?$query_string; apontando para o mesmo arquivo.

Início

Ciclo de Vida da Requisição

Todo request HTTP passa pelo mesmo caminho, do .htaccess até a resposta final.

1. public/index.php

Ponto de entrada único (todo tráfego é reescrito para cá pelo .htaccess). Apenas requer bootstrap/app.php e chama $app->run().

2. bootstrap/app.php

Define as constantes de caminho (ROOT_PATH, VIEW_PATH, STORAGE_PATH etc.), carrega o autoload do Composer, o .env (via vlucas/phpdotenv) e config/app.php. Em seguida inicia a sessão (Session::start() + ageOldInput()), tenta reautenticar via cookie "lembrar de mim" e devolve uma instância de Core\Application.

3. Application::__construct()

Instancia Request e Router, configura o tratamento de erros (set_error_handler + register_shutdown_function quando APP_DEBUG=true) e aplica os headers de segurança básicos + SecurityHeadersMiddleware globalmente.

4. Application::run()

Registra o Router na instância estática (Router::setInstance(), usada pela função global route()), carrega routes/web.php e chama $router->dispatch().

5. Router::dispatch()

Percorre as rotas registradas até casar método HTTP + URI. Executa os middlewares da rota em ordem e, se nenhum interromper o fluxo, chama callAction().

6. Router::callAction()

Instancia o Controller e usa ReflectionMethod para montar os argumentos do método: parâmetros de rota são convertidos para o tipo declarado (int, float, bool) e parâmetros tipados como FormRequest são instanciados automaticamente (já validados nesse ponto).

7. Controller → Service → Repository → Model

O controller delega a lógica de negócio a um Service (opcional) e/ou acessa dados via Repository ou diretamente via Model. Ver Camadas.

8. Resposta

O controller responde via view() (HTML), json()/jsonSuccess()/ jsonError() (API) ou redirect(). Exceptions não capturadas voltam para Application::handleException(), que loga e renderiza a página de erro apropriada.

Arquitetura

Camadas

O fluxo recomendado é Controller → Service → Repository → Model, mas o framework não obriga: Repository é opcional, e um controller simples pode acessar o Model diretamente.

Controller
Recebe o Request, delega para Service/Repository/Model e devolve uma resposta HTTP (view, JSON ou redirect). Nunca contém SQL ou regra de negócio complexa.
Service opcional
Orquestra regras de negócio que envolvem múltiplos passos (ex.: criar usuário + enviar e-mail + logar). Não acessa $_POST/$_SESSION nem faz redirect — recebe dados já validados e devolve dados/exceções.
Repository opcional
Encapsula as queries de um Model. Existe para testabilidade (pode ser mockado) e para centralizar queries compostas. Se a aplicação é pequena, pular esta camada e usar o Model direto é aceitável.
Model
Representa uma tabela. Fornece CRUD e query builder fluente sobre PDO (Core\Model).
Database
Singleton PDO. Todo acesso ao banco, de qualquer camada, passa por aqui.
💡
Quando pular o Repository

Para CRUDs simples sem lógica de consulta reutilizável, chamar o Model diretamente do Controller (ou do Service) é uma escolha válida do projeto. Adicione um Repository quando a mesma query composta começar a se repetir em mais de um lugar, ou quando for necessário mockar o acesso a dados em testes.

Exemplo completo das 4 camadas

app/Models/Product.php
// app/Models/Product.php
namespace App\Models;
use Core\Model;

class Product extends Model
{
    protected string $table    = 'products';
    protected array  $fillable = ['name', 'price', 'category_id'];
}
app/Repositories/ProductRepository.php
// app/Repositories/ProductRepository.php
namespace App\Repositories;
use Core\Repository;
use App\Models\Product;

class ProductRepository extends Repository
{
    protected string $modelClass = Product::class;

    public function findByCategory(int $categoryId): array
    {
        return $this->model()->where('category_id', $categoryId)->orderBy('name')->get();
    }
}
app/Services/ProductService.php
// app/Services/ProductService.php
namespace App\Services;
use Core\Service;
use App\Repositories\ProductRepository;

class ProductService extends Service
{
    private ProductRepository $products;

    public function __construct()
    {
        $this->products = new ProductRepository();
    }

    public function create(array $data): string
    {
        // Regra de negócio: preço não pode ser negativo (validação de FormRequest já
        // garante isso normalmente — aqui é uma segunda camada de proteção de domínio)
        if ((float) $data['price'] < 0) {
            $this->fail('Preço inválido.');
        }

        $id = $this->products->create($data);
        if ($id === false) {
            $this->fail('Não foi possível criar o produto.');
        }

        return $id;
    }
}
app/Controllers/ProductController.php
// app/Controllers/ProductController.php
namespace App\Controllers;
use Core\Controller;
use App\Services\ProductService;
use App\Requests\Products\StoreProductRequest;

class ProductController extends Controller
{
    private ProductService $service;

    public function __construct()
    {
        parent::__construct();
        $this->service = new ProductService();
    }

    public function store(StoreProductRequest $request): void
    {
        // O FormRequest já validou e interrompeu a requisição se inválido —
        // ao chegar aqui, $data está garantidamente limpo.
        $data = $this->validateRequest($request);

        try {
            $id = $this->service->create($data);
            $this->redirectWith('dashboard/products', 'success', 'Produto criado com sucesso.');
        } catch (\RuntimeException $e) {
            // Service::fail() lança RuntimeException com código 422
            $this->redirectWith('dashboard/products/create', 'error', $e->getMessage());
        }
    }
}
Arquitetura

Router

Core\Router mapeia URIs para Controllers. Suporta parâmetros dinâmicos, grupos com prefixo/middleware compartilhados, rotas nomeadas e injeção automática de FormRequest.

MétodoAssinaturaDescrição
get/post/put/patch/delete(string $path, array|string $action, array $middlewares = [])Registra uma rota para o verbo HTTP correspondente. $action aceita [Controller::class, 'metodo'] ou a string 'Controller@metodo'.
match(array $methods, string $path, array|string $action, array $middlewares = [])Registra a mesma rota para múltiplos verbos de uma vez.
resource(string $path, string $controller, array $only = [])Gera as 7 rotas REST padrão (index, create, store, show, edit, update, destroy) nomeadas como {recurso}.{acao}. Use $only para gerar apenas algumas.
group(array $options, callable $callback)Agrupa rotas com prefix e/ou middleware compartilhados. Suporta grupos aninhados (empilha prefixos e middlewares).
name(string $name): staticNomeia a última rota registrada, encadeado após get()/post()/etc.
route(string $name, array $params = []): stringGera a URL absoluta de uma rota nomeada, substituindo {param} pelos valores informados.
routes/web.php
// routes/web.php  — $router já está disponível no escopo (injetado por Application::run())
use App\Controllers\HomeController;
use App\Controllers\AuthController;
use App\Controllers\DashboardController;
use Core\Router;

$router->get('/', [HomeController::class, 'index'])->name('home');

// Grupo com prefixo + middleware compartilhado (aninhável)
$router->group(['prefix' => '/auth', 'middleware' => ['GuestMiddleware']], function (Router $r) {
    $r->get('/login',  [AuthController::class, 'loginForm'])->name('auth.login');
    $r->post('/login', [AuthController::class, 'login'], ['CsrfMiddleware', 'RateLimitMiddleware:login']);
});

// Parâmetro dinâmico obrigatório + tipagem automática (int) no método do controller
$router->get('/products/{id}', [ProductController::class, 'show']);

// CRUD REST completo em uma linha — gera as 7 rotas nomeadas products.index, products.show...
$router->resource('/products', ProductController::class);

// Gerando URL a partir do nome da rota (na view ou no controller)
echo route('products.show', ['id' => 42]); // → http://localhost:8000/products/42
ProductController.php
// No método do controller: o {id} da URI é convertido para int automaticamente
public function show(int $id): void
{
    $product = (new \App\Models\Product())->find($id);

    if (!$product) {
        // Lança uma exceção que Application::resolveHttpCode() converte para HTTP 404
        // (baseado na palavra "not found"/"não encontrado" na mensagem)
        throw new \RuntimeException('Produto não encontrado.', 404);
    }

    $this->view('products.show', ['product' => $product]);
}
⚠
Parâmetros opcionais e Reflection

Rotas como /posts/{slug?} usam ({param}?). Se o parâmetro não vier na URI, o Router injeta o valor padrão declarado no parâmetro do método do controller via ReflectionParameter::getDefaultValue() — portanto o método precisa declarar um valor padrão (ex.: function index(?string $slug = null)) ou o dispatch lança RuntimeException por parâmetro obrigatório ausente.

Core

Application

Core\Application é o kernel: orquestra boot, dispatch e tratamento centralizado de exceções. É instanciada uma única vez por requisição, em bootstrap/app.php, e não deve ser instanciada manualmente em outro lugar.

MétodoRetornoDescrição
__construct()—Instancia Request e Router, configura o tratamento de erros PHP e aplica os headers de segurança (globalmente, inclusive em páginas de auth).
run()voidRegistra o Router na instância estática, carrega routes/web.php e despacha a requisição. Qualquer \Throwable não capturado no caminho é interceptado aqui.
handlePhpError()boolHandler de set_error_handler(): converte erros/avisos PHP em ErrorException (apenas quando APP_DEBUG=true).
handleShutdown()voidHandler de register_shutdown_function(): captura erros fatais (E_ERROR, E_PARSE, E_CORE_ERROR, E_COMPILE_ERROR) que não passam por set_error_handler().

Resolução do HTTP status code de uma exceção

resolveHttpCode() decide o código HTTP na seguinte ordem de prioridade:

  1. Se $e->getCode() for um inteiro válido entre 400–599, usa ele diretamente (ex.: throw new \RuntimeException('Produto não encontrado.', 404)).
  2. Se o nome da classe da exceção contiver NotFoundException, UnauthorizedException, ForbiddenException, ValidationException ou CsrfException, mapeia para 404/401/403/422/419 respectivamente.
  3. Se a mensagem contiver palavras-chave ("not found"/"não encontrado", "unauthorized"/"não autorizado", "forbidden"/"proibido"), infere o código.
  4. Caso contrário, 500.
exemplo.php
// Forma mais explícita e recomendada — passa o código HTTP direto na exceção
throw new \RuntimeException('Pedido não encontrado.', 404);

// Também funciona por inferência de mensagem (menos explícito, evite em código novo)
throw new \RuntimeException('Usuário não encontrado no sistema.'); // → resolve como 404
ℹ
Debug vs Produção

Com APP_DEBUG=true, renderDebugPage() mostra uma página estilo Laravel/Ignition com o trecho de código de cada frame do stack trace. Com APP_DEBUG=false, renderProductionError() procura app/Views/errors/{codigo}.php (ex.: 404.php) e cai para errors/generic.php se não existir. Em ambos os casos, o erro é sempre gravado via Logger::error().

Classe base abstrata de todos os controllers. Fornece renderização de views, redirecionamento, respostas JSON, flash messages, validação e injeção automática de CSRF em formulários. Nunca deve conter regra de negócio — apenas infraestrutura de resposta HTTP.

💡
Injeção automática de CSRF

Toda página renderizada via view() passa por injectCsrfTokens(), que injeta csrf_field() em qualquer <form> com method diferente de GET que ainda não tenha um campo _csrf_token. Forms sem atributo method (GET implícito do HTML) são ignorados. Não é necessário chamar isso manualmente.

public function destroy(int $id): void
{
    $ok = (new \App\Repositories\ProductRepository())->delete($id);

        $ok
            ? $this->jsonSuccess('Produto removido.')

Validação

MétodoAssinaturaDescrição
validate(array $data, array $rules, string $redirectBack = ''): arrayValida um array inline (sem FormRequest). Em caso de falha, salva erros + old input na sessão e redireciona de volta.
validateRequest(object $request, string $redirectBack = '', ?array $flashOnly = null): arrayValida um FormRequest já instanciado. exemplo.php
// Exemplo com FormRequest injetado automaticamente pelo Router
public function store(\App\Requests\Users\StoreUserRequest $request): void
{
    // Não reenvia o campo "password" no old-input em caso de erro de validação
    $data = $this->validateRequest($request, redirectBack: 'dashboard/users/create', flashOnly: ['name', 'email']);

    $id = (new \App\Models\User())->create($data);
    $this->redirectWith('dashboard/users', 'success', 'Usuário criado.');
}

// Exemplo de validação inline, sem FormRequest
public function quickUpdate(int $id): void
{
    $data = $this->validate($this->request->all(), [
        'name' => 'required|min:2|max:100',
    ]);

    (new \App\Models\User())->update($id, $data);
    $this->redirectWith('dashboard/users', 'success', 'Atualizado.');
}

ℹ
"Lembrar de mim" — como funciona

Um token de 64 chars é gerado, armazenado como hash SHA-256 no banco (nunca em texto puro) e enviado num cookie HttpOnly + Secure + SameSite=Lax com validade de 30 dias. Em cada requisição sem sessão ativa, Auth::recoverFromCookie() (chamado no bootstrap) compara o hash do cookie com hash_equals() e, se válido e não expirado, reautentica silenciosamente e rotaciona o token.

app/Services/OrderService.php
namespace App\Services;
use Core\Service;
use App\Repositories\OrderRepository;
use App\Repositories\ProductRepository;

class OrderService extends Service
{
    public function __construct(
        private OrderRepository $orders = new OrderRepository(),
        private ProductRepository $products = new ProductRepository()
    ) {}

    public function checkout(int $userId, array $items): string
    {
        if (empty($items)) {
            $this->fail('O carrinho está vazio.');
        }

        // transaction() faz commit automatico em sucesso, rollback em qualquer excecao
        return $this->transaction(function () use ($userId, $items) {
            $total = 0;
            foreach ($items as $item) {
                $product = $this->products->findById($item['product_id']);
                if (!$product) {
                    $this->fail("Produto {$item['product_id']} não existe.");
                }
                $total += $product->price * $item['qty'];
            }

            return $this->orders->create(['user_id' => $userId, 'total' => $total]);
        });
    }
}

FormRequests

FormRequest (base)

App\Requests\FormRequest é inspirada no FormRequest do Laravel, adaptada para PHP puro. Centraliza captura de dados, sanitização, autorização, validação e mensagens customizadas — tudo resolvido automaticamente no construtor.

Fluxo interno

1. Captura

Body JSON (se Content-Type: application/json) ou $_POST + nomes de $_FILES.

2. authorize()

Se retornar false, responde 403 (JSON ou flash+redirect) e encerra a execução — o Controller nunca chega a receber o objeto.

3. sanitize()

Por padrão aplica Request::sanitizeValue() em todos os campos; pode ser sobrescrito.

4. rules() + Validator

Valida os dados sanitizados contra as regras declaradas.

5. messages()

Sobrescreve mensagens padrão do Validator por chave 'campo.regra'.

Métodos a implementar

MétodoObrigatório?Descrição
authorize(): boolSim (abstract)Autorização da requisição — Auth::check(), Auth::is('admin'), ou true se sempre permitido.
rules(): arraySim (abstract)Regras no formato do Core\Validator.
messages(): arrayNão (padrão: [])Mensagens customizadas, chave 'campo.regra'.
sanitize(): arrayNão (padrão: sanitização automática)Sobrescreva para transformações específicas (ex.: strtolower em e-mail).

API pública (usada no controller)

MétodoAssinaturaDescrição
fails / passes(): boolA validação falhou/passou?
errors(): arrayTodos os erros, ['campo' => ['msg', ...]].
firstError(?string $field = null): ?stringPrimeiro erro de um campo, ou primeiro erro geral.
validated(): arrayDados que passaram em todas as regras, já sanitizados — use este array no Service/Model, nunca $_POST direto.
get(string $field, mixed $default = null): mixedAtalho para validated()[$field].

ℹ
Como funciona por baixo dos panos

Cli\Kernel faz o parse de $argv (nome do comando, argumentos posicionais e opções --flag/--key=valor), resolve a classe do comando no mapa registerCommands() e chama handle(): bool. Todo comando estende a classe base Cli\Command, que fornece arg(), option(), hasOption(), ask() (confirmação interativa) e generateFile() (geração a partir de stubs em cli/Stubs/).

Banco de Dados

Migrations & Seeds

Migrations são arquivos .sql puros e numerados em database/migrations/, executados por Cli\Migrator. Não há DSL PHP para schema (ao contrário do Laravel) — o SQL é escrito diretamente.

Como o Migrator funciona

1. Bootstrap mínimo

bootstrapEnvironment() carrega .env e config/app.php — necessário porque o binário mvc não passa pelo bootstrap/app.php completo da aplicação web.

2. Garante o banco

ensureDatabaseExists() conecta sem dbname no DSN (já que o banco pode não existir ainda) e executa CREATE DATABASE IF NOT EXISTS (ou DROP + CREATE se --fresh).

3. Tabela de controle

Cria (se não existir) a tabela migrations, que registra quais arquivos já rodaram (UNIQUE KEY em migration).

4. Executa em ordem

Lista os arquivos com glob('*.sql') + natsort() (ordena 001_..., 002_... numericamente), separa cada arquivo em statements por ; (removendo comentários --, # e /* */) e executa cada um via Database::execMigration().

5. Registra

Após rodar um arquivo com sucesso, insere seu nome na tabela migrations (INSERT IGNORE) para não rodar de novo em execuções futuras — a menos que seja --fresh, que ignora esse controle e roda tudo de novo em um banco recém-criado.

001_create_base_tables.sql
-- database/migrations/001_create_base_tables.sql
CREATE TABLE IF NOT EXISTS users (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(180) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(40) NOT NULL DEFAULT 'member',
    active TINYINT(1) NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_active (active)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS password_resets (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(180) NOT NULL,
    token VARCHAR(100) NOT NULL UNIQUE,
    expires_at DATETIME NOT NULL,
    used TINYINT(1) NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_token (token)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;
ℹ
Migrations já existentes no projeto

001_create_base_tables.sql cria users e password_resets. 002_add_rate_limit_table.sql adiciona as colunas remember_token / remember_token_expires_at em users (usadas por Core\Auth) e um índice em password_resets — apesar do nome do arquivo, ela não cria uma tabela nova de rate limit (o rate limiting atual é feito em arquivo, ver RateLimitMiddleware), o nome reflete a intenção original do arquivo.

Seeds

Seeders são scripts PHP independentes em database/seeds/ — cada um faz seu próprio bootstrap mínimo (lê .env manualmente, conecta via PDO direto) para poder ser executado tanto via php mvc seed:run quanto diretamente com php database/seeds/Arquivo.php.

database/seeds/UserSeeder.php
// database/seeds/UserSeeder.php (existente no projeto)
$users = [
    ['name' => 'Administrador', 'email' => 'admin@example.com', 'password' => 'admin123', 'role' => 'admin'],
    ['name' => 'Usuário Demo',  'email' => 'user@example.com',  'password' => 'user123',  'role' => 'member'],
];

foreach ($users as $u) {
    // Idempotente - verifica existencia antes de inserir
    $stmt = $pdo->prepare("SELECT id FROM users WHERE email = :email");
    $stmt->execute([':email' => $u['email']]);

    if ($stmt->fetch()) {
        echo "  ! {$u['email']} já existe — ignorado.\n";
        continue;
    }

    $hash = password_hash($u['password'], PASSWORD_BCRYPT, ['cost' => 12]);
    $pdo->prepare("INSERT INTO users (name, email, password, role, active) VALUES (?, ?, ?, ?, 1)")
        ->execute([$u['name'], $u['email'], $hash, $u['role']]);
}
⚠
Seeders são idempotentes por convenção, não por garantia da plataforma

Tanto o UserSeeder existente quanto o stub gerado por php mvc make:seed checam duplicidade manualmente (SELECT ... WHERE antes do INSERT). Isso é uma convenção do projeto, não um mecanismo automático — um seeder customizado que pular essa checagem vai duplicar registros a cada execução.

Construindo uma API REST

O grupo /api já existe em routes/web.php (vazio, pronto para uso). Combine Request::json(), os métodos json*() do Controller e FormRequest (que já suporta body JSON automaticamente) para expor endpoints.

exemplo.php
// routes/web.php
$router->group(['prefix' => '/api', 'middleware' => ['AuthMiddleware']], function ($r) {
    $r->get('/products',      [Api\ProductController::class, 'index']);
    $r->post('/products',     [Api\ProductController::class, 'store'], ['CsrfMiddleware']);
    $r->get('/products/{id}', [Api\ProductController::class, 'show']);
});
app/Controllers/Api/ProductController.php
namespace App\Controllers\Api;
use Core\Controller;
use App\Models\Product;
use App\Requests\Products\StoreProductRequest;

class ProductController extends Controller
{
    public function index(): void
    {
        $page = (int) $this->request->get('page', 1);
        $result = (new Product())->paginate(perPage: 20, page: $page);

        $this->jsonSuccess('OK', $result);
    }

    public function show(int $id): void
    {
        $product = (new Product())->find($id);

        if (!$product) {
            // Caminho de erro: 404 em formato JSON
            $this->jsonError('Produto não encontrado.', 404);
        }

        $this->jsonSuccess('OK', ['product' => $product]);
    }

    public function store(StoreProductRequest $request): void
    {
        // FormRequest::captureInput() ja le o body JSON automaticamente
        // quando Content-Type: application/json - nao precisa de tratamento especial
        $data = $this->validateRequestApi($request);

        $id = (new Product())->create($data);
        $this->jsonSuccess('Produto criado.', ['id' => $id], 201);
    }

    // Helper local: versao de validateRequest() que responde JSON em vez de redirecionar
    // (validateRequest() do Core\Controller sempre redireciona - nao serve para API pura)
    private function validateRequestApi(object $request): array
    {
        if ($request->fails()) {
            $this->jsonError($request->firstError(), 422, ['errors' => $request->errors()]);
        }
        return $request->validated();
    }
}
⚠
validateRequest() do Controller sempre redireciona

Core\Controller::validateRequest() foi desenhado para fluxo de formulário HTML — em caso de falha, ele sempre chama redirect(). Para uma API pura, chame $request->fails() / $request->errors() diretamente e responda com jsonError(), como no exemplo acima, em vez de usar validateRequest().

ℹ
CSRF em APIs autenticadas por sessão

Se a API compartilha a mesma sessão do site (cookies), mantenha CsrfMiddleware nas rotas de escrita e envie o token via header X-CSRF-Token. Para uma API pública sem sessão (token Bearer, por exemplo), CsrfMiddleware não se aplica — CSRF é um problema específico de autenticação baseada em cookie.

Resumo das proteções já implementadas pelo framework e o que ainda é responsabilidade do desenvolvedor da aplicação.

1) APP_ENV=production e APP_DEBUG=false no .env do servidor; 2) APP_KEY gerado com php mvc key:generate (nunca reaproveitar a chave de desenvolvimento); 3) HTTPS ativo (necessário para os cookies Secure funcionarem); 4) remover quaisquer chamadas a dd()/dump(); 5) revisar o CSP em SecurityHeadersMiddleware contra os domínios realmente usados pelo front-end.
